nxm-config · Explainer

Come funziona la configurazione NXM

Una lettura unica e tipizzata della configurazione della piattaforma NXM, con override ambientali espliciti e validazione prima che il valore raggiunga i chiamanti.

1. Scoperta della root

ConfigPaths::discover() legge NXM_CONFIG_HOME se impostata; altrimenti usa ~/.nxmconfig. with_root() è disponibile per test e deployment isolati.

2. Directory e file

provider/ — configurazione generata dei provider
logs/ — log rotanti
data/ — dati applicativi
config.toml — configurazione generale

ensure_directories() crea le directory mancanti; load_or_create_config() scrive un file di default quando config.toml non esiste.

3. Modello tipizzato

GeneralConfig aggrega ServerSettings, DatabaseSettings e GenerationSettings. I driver supportati sono sqlite, postgres e mongodb.

4. Precedenza e override

I valori del file TOML vincono sulle integrazioni di default. Le variabili NXM_* sovrascrivono le chiavi supportate: NXM_SERVER_HOST, NXM_SERVER_PORT, NXM_CORS_ORIGINS, NXM_DATABASE_DRIVER, NXM_DATABASE_URL. Il risultato viene validato prima di essere restituito.

5. Configurazione MCP

I file di configurazione per i server MCP vivono in ~/.nxmconfig/<nome>_config.json (preferito, standard di mercato) oppure TOML. Il crate risolve percorso e formato, valida JSON/TOML e offre helper di lettura/scrittura.
